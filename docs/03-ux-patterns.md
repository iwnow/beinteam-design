# UX-паттерны

Эти правила важнее конкретной разметки: при сборке приложения их нужно воспроизвести поведенчески, даже если вёрстка компонента будет другой.

## 1. Боковая панель вместо модалки

**Правило:** любая работа с сущностью — просмотр, создание, редактирование, оплата, история — открывается в правой панели. Центральных модальных окон для данных нет.

| Ширина | Поведение панели |
|---|---|
| ≥ 1280 px | **push**: панель встаёт справа, контент сжимается (`.app.has-drawer .main { padding-right: var(--drawer-w) }`). Расписание/канбан остаются видны и кликабельны |
| 768–1279 px | **overlay**: панель поверх, полупрозрачный backdrop, клик по нему закрывает |
| < 768 px | панель на весь экран (`--drawer-w: 100vw`), кнопка закрытия слева сверху привычна для мобилы |

Анатомия (`.drawer`):
- **head** — `.overline` (тип и номер: «Бронь #245992 · заказ #120461»), `h2` (главное: клиент/название), `.drawer-sub` (статус, мета), справа кнопка закрытия. Действия «WhatsApp / Позвонить / Изменить» — строкой под заголовком (`.drawer-actions`), не рядом с ним.
- **body** — скроллится; секции `.drawer-section > h3`; деньги `.drawer-money` или `.hero-money`; итоги `.summary-box`.
- **foot** — прилипает к низу; слева вторичное (Отмена / Удалить), справа одна главная оранжевая кнопка с суммой, если речь о деньгах: «Провести 6 750 ₽».
- Ширина 460 px; `.drawer-wide` 640 px — для карточек с вкладками (клиент, заказ, задача, результат чек-листа, настройки объекта).

Поведение, которое нужно реализовать:
- **Стек.** Действие внутри панели открывает следующую панель поверх (`.is-stacked` у нижней): Бронь → Оплата → Ссылка на оплату; Заказ → Бронь-позиция / Товар; Клиент → Редактирование / Юр. лицо. Закрытие верхней возвращает к предыдущей без потери введённого.
- **Выделение источника.** Строка/карточка/событие, открывшее панель, получает `.is-selected` — пользователь видит, что именно открыто.
- **Esc** закрывает верхнюю панель; фокус переходит в панель при открытии и возвращается на источник при закрытии; внутри панели — focus trap только в режиме overlay (в push-режиме пользователь может кликать по странице).
- **Результат.** Закрытие панели с результатом обновляет данные страницы (замена текущего события `modal-close`).
- **URL.** Открытая панель отражается в адресе: `?booking=245992`, `?order=120461`, `?client=…`, `?task=…`. Ссылка из уведомления, поиска или чата открывает страницу сразу с панелью. В макетах это упрощено до `page.html#name`.
- **Несохранённые изменения.** При закрытии формы с изменениями — не диалог, а inline-полоса в футере панели «Есть несохранённые изменения · Сохранить · Отменить» (в макетах не нарисовано — см. 08-attention.md).

## 2. Подтверждения без диалогов

| Ситуация | Паттерн | Пример в макетах |
|---|---|---|
| Обратимое действие (отменить бронь, отозвать доступ, удалить черновик) | Выполнить сразу + **тост «Вернуть»** на 5–8 с; запрос на бэк можно отложить до истечения тоста | `data-toast="…" data-toast-action="Вернуть"` |
| Необратимое или с последствиями (удалить операцию кассы, удалить позицию заказа с возвратом денег) | **Inline-подтверждение** внутри панели: блок с последствием («Баланс станет 33 500 ₽») и кнопками «Удалить / Отмена» | `cashbox.html#tx`, состав в `orders.html#order` |
| Нельзя выполнить | Кнопка `disabled` + текст причины рядом, а не alert после клика | «Открыть бар» в `object.html` |
| Ошибка валидации | Под полем (`.field.is-invalid` + `.error-text`), кнопка действия неактивна | «Сумма больше баланса кассы» в `cashbox.html#expense` |

Нативные `alert()` / `confirm()` запрещены.

## 3. Формы

- Подпись над полем всегда видна (не placeholder вместо подписи). Подсказка `.hint` под полем, ошибка `.error-text` вместо подсказки.
- Две колонки (`.form-grid`) на десктопе, одна на мобиле; длинные поля — `.span-2`.
- Сумма — крупный инпут с «₽» справа; рядом пересчёт последствий: «Баланс после операции: 36 250 ₽».
- Выбор из 2–5 вариантов — сегмент (`.seg`), а не select: способ оплаты, Заказ/Блокировка, Физлицо/Юрлицо.
- Выбор времени — сетка слотов с ценой (`.slot-pick`), занятые перечёркнуты и неактивны. Цена берётся из `booking-slots`, итог — из `booking-calculate`.
- Клиент в новой брони/заказе — комбобокс с поиском и строкой «+ Новый клиент» внутри выпадающего списка; новый клиент создаётся во вложенной панели или раскрывающемся блоке, а не в модалке 3-го уровня.
- Повтор брони — выбор дней недели и даты окончания, с превью количества броней и суммы до создания.

## 4. Списки и фильтры

- Поиск + 1–3 select + чипы быстрых фильтров (`.chip`, одиночный или мультивыбор). Активные фильтры видны всегда; «Сбросить» — в пустом состоянии.
- Канбан заказов: колонки = статусы заказа (по полю `sort`), карточку можно перетащить → смена статуса (`PUT /manager/orders/{id}/state/{state_id}`) + тост «Вернуть». Альтернативный вид — таблица (переключатель `.seg` «Канбан | Список»).
- Таблицы на мобиле превращаются в карточки (`.table-wrap.stack-mobile`, второстепенные колонки `td.hide-mobile`). Широкие таблицы без такого режима (чек-листы) — горизонтальный скролл внутри контейнера, первая колонка закреплена.
- Пустые состояния (`.empty`) — иконка, что случилось, что сделать: «Никого не нашли · Проверьте написание · Сбросить фильтры».
- Разделители дней в лентах операций с дневным итогом (`tr.day-sep` в кассе).

## 5. Навигация и глобальные функции

- Сайдбар: группы «Работа» (Сегодня, Расписание, Заказы, Клиенты, Задачи), «Сеть» (Объекты, Кассы, Чек-листы, Отчёты), «Управление» (Настройки). Сверху — переключатель компании, снизу — пользователь, объект и смена. Сворачивается до иконок.
- Топбар: хлебные крошки (Компания / Объект / Площадка), поиск `Ctrl K`, тема, чат WhatsApp, уведомления.
- **`Ctrl K`** — единственный оверлей: поиск по клиентам, заказам, броням (`GET /search?types=…&q=…`) и командам («Новая бронь», «Записать расход»); результат открывает боковую панель поверх текущей страницы.
- Мобильный таббар: Расписание, Заказы, Клиенты, Объекты, Сегодня; сайдбар уезжает в бургер.
- Новый экран **«Сегодня»** (`dashboard.html`) — стартовая страница администратора: ближайшие брони, загрузка площадок по часам, «требует внимания», смена, кассы.

## 6. Обратная связь

- Тост внизу по центру (на мобиле над таббаром), одна строка + необязательное действие. Без тостов «Успешно сохранено» на каждое поле: достаточно закрытия панели и обновления строки.
- Реалтайм (WebSocket `ORDER_CREATED`, `WCHAT_MSG`) — точка на иконке уведомлений/чата и тост с действием «Открыть», а не alert.
- Загрузка: скелетоны в таблицах и панелях (в макетах не нарисованы), кнопка действия с индикатором и неактивна во время запроса.

## 7. Доступность

- Контраст текста AA в обеих темах (поэтому `--accent-text` для оранжевого текста и чёрный текст на оранжевой кнопке).
- Видимый фокус: `:focus-visible` — оранжевый outline 2 px; у полей ввода — рамка `--accent` и кольцо `0 0 0 3px var(--focus)`.
- Статус всегда словом; иконки-кнопки с `aria-label`.
- `prefers-reduced-motion` отключает анимации панелей (уже в `app.css`).
- Панель: `role="dialog"` только в overlay-режиме; в push-режиме — `role="complementary"` с `aria-label`.
