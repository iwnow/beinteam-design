# На что обратить внимание при сборке приложения

Макеты статичны и местами упрощены. Ниже — что в них нарисовано «для вида», где решения ещё не приняты и где легко ошибиться с данными.

## 1. Данные и API — ловушки

1. **У брони нет статуса.** Цвет события в расписании и бейдж в панели брони — это статус **заказа** брони. Бронь без заказа — блокировка (техбронь). Не заводить в UI «статус брони».
2. **Статусы заказа — справочник, а не enum.** Брать из `GET /manager/order-states` (поля `code`, `name`, `sort`). Есть пользовательские статусы без системного кода (на тесте — «Перезвонить»): им тон `info`. Колонки канбана — по `sort`. В макете канбан показывает 5 колонок для примера.
3. **Способы оплаты** — `CASH`, `CARDTF`, `TERM`, `QR`, `BNKACC`, `CUSTACC`, `ACQ`. В разных панелях макетов сегмент оплаты показывает разный набор (где-то «Счёт клиента», где-то «Ссылка») — в приложении набор строится из касс объекта (`GET /manager/objects/{object_id}/cashboxes`, флаги `is_hidden`, `allow_manual_payment`) и прав пользователя. «Счёт клиента» показывать только если есть право на баланс и баланс > 0 (`GET /customers/{id}/account-balance`).
4. **Оплата частями по позициям.** `POST /manager/orders/{order_id}/transactions` принимает `product_payments[{id, amount}]` — сумма распределяется по позициям заказа. Отсюда чекбоксы в составе заказа и кнопка «Оплатить выбранное · N ₽».
5. **Удаление позиции заказа** с флагом `cancel_payments` («вернуть деньги на счёт клиента»). Это и есть inline-подтверждение в `orders.html#order`; в текущем UI оно было третьим уровнем модалок.
6. **Операции кассы:** ручную операцию можно удалить (`DELETE …/transactions/{transaction_id}`), операцию по заказу — нет (в макете — подпись в `cashbox.html#tx`). Баланс «после операции» считается на клиенте от `account.balance` кассы.
7. **Суммы — целые числа.** В текущем коде деления на 100 нет, суммы выводятся как рубли. Перед переносом подтвердить с бэкендом, чтобы не получить ×100.
8. **Склейка запросов броней и слотов.** Расписание запрашивает брони и тарифные слоты по диапазону дат; текущий код склеивает близкие запросы и режет ответ (`withQueueRequests` в `src/lib/bitapi/methods/manager.ts`, `places.ts`). Сохранить это поведение в сторе расписания, иначе листание недель даст лавину запросов.
9. **Чек-листы — это задачи** (`process_id` 2 — смена, 3 — бар). Колонки таблицы результатов задаются вручную и сверяются с `checklist.content` актуальной задачи, а не с `checklist_result` (это история, там бывают устаревшие поля). Подробно — раздел «Чеклисты» в `web/CLAUDE.md`. Заполнение чек-листа (SurveyJS) — отдельная полноэкранная страница, не панель.
10. **Поиск** — `GET /search?types=…&q=…&company_id=…` (не POST).
11. **Права.** Кнопки действий (оплата, удаление операций, баланс клиента, инкассация, настройки) скрываются по правам объекта/компании (`ADMIN`, `VIEWER`, `ENCASHER`, `TASK_*` и флаги `ORDER_*`, `PB_*`, `CASHBOX_OP_*`, `CUSTOMER_BALANCE_READ`). В макетах всё показано как для администратора.
12. **Время.** Все даты выводить во временной зоне объекта (текущий код использует `date-fns-tz`). Расписание объекта 08:00–23:00 в макете — пример, реальные границы берутся из графика работы площадки.
13. **Аутентификация:** логин/пароль и Telegram, access/refresh в cookie (`bit_ta`, `bit_tr`), один повтор запроса на 401 через refresh, перевоплощение администратора (`/token/impersonate/...`) — в макетах экрана перевоплощения нет, место ему — меню пользователя в сайдбаре.
14. **Реквизиты юрлица в API — integer** (ИНН, КПП, ОГРН, БИК). Ведущие нули теряются, а в UI поля должны быть строковыми с маской. Нужна правка схемы на бэкенде.
15. **НДС ЮKassa** — `YookassaVatCode` 1..6, а не проценты. В макете select показывает проценты; в приложении подписи к кодам брать из справочника ЮKassa.
16. **Выбор кассы при оплате.** В `POST /manager/orders/{order_id}/transactions` нет `cashbox_id` — касса определяется способом оплаты. Сегмент «способ оплаты» = выбор кассы.
17. **Количество товара в заказе.** PATCH позиции меняет только `amount`; изменение `quantity` степпером из макета — уточнить у бэкенда.
18. Полный список того, что в макетах есть, а в API не найдено, — раздел «Сводка API, не найденного в openapi» в [04-screens.md](04-screens.md). Его стоит отдать бэкенду до начала сборки.

## 2. Что в макетах нарисовано, но не работает

| Что | Где | Что сделать в приложении |
|---|---|---|
| Фильтры, поиск, чипы, select периода ничего не фильтруют | все списки | реальная фильтрация (параметры запросов `…/search`), фильтры — в query-параметрах URL |
| Пустые состояния скрыты атрибутом `hidden` | clients, tasks | показывать по результату запроса |
| Drag-n-drop канбана — только `draggable` и курсор | orders | CDK drag-drop → `PUT /manager/orders/{order_id}/state/{state_id}` + тост «Вернуть», оптимистичное обновление |
| Кнопки «⋯» в строках состава заказа | orders | меню: изменить, перенести, удалить |
| Тосты «Вернуть» ничего не откатывают | везде | отложенный запрос или обратная операция |
| Панели-заглушки `drawer-order`, `drawer-client` в schedule, `drawer-order-stub` в clients | schedule, clients | один и тот же компонент панели заказа/клиента, полные версии — в `orders.html#order` и `clients.html#client` |
| Панель настроек объекта скопирована в objects и object | objects, object | один компонент |
| Demo-несостыковки: «Похожий клиент: Анна К.» открывает карточку «Команды «Вектор»» | clients | при реальных данных исчезнут |
| Линия «сейчас» в расписании и на «Сегодня» стоит статично | schedule, dashboard | считать от текущего времени объекта, обновлять раз в минуту |
| `Ctrl K` показывает фиксированный список | все | живой поиск с debounce |
| Графики отчётов — CSS-имитация | reports | см. открытый вопрос №4 |
| Даты в `checklists.html` — нативный `<input type="date">` (формат зависит от локали браузера) | checklists | датапикер с русской локалью и диапазоном |

## 3. Чего в макетах нет — нужно спроектировать при сборке

- **Состояния загрузки** (скелетоны таблиц, панелей, расписания) и **ошибок** запросов (inline в панели + повтор).
- **Несохранённые изменения** при закрытии панели-формы: inline-полоса в футере «Есть изменения · Сохранить · Отменить» (без диалога).
- **Панель чата WhatsApp** (`wchat`) и **панель уведомлений** — в топбаре есть только иконки. Обе — правые панели того же `DrawerService`.
- **Загрузка фото/обложки площадки, камеры площадки** — в `drawer-place-edit` есть поля, без превью и обрезки.
- **Горящие предложения (SlotOffer)** — сущность есть в API, экрана нет; логичное место — вкладка в расписании или в настройках объекта.
- **База знаний** (вкладка компании для Campus, `checkCampus`) — не перерисовывалась.
- **Онлайн-эквайринг (ЮKassa/Точка)** — в настройках объекта только переключатели, без мастера подключения.

## 4. Открытые вопросы (нужно решение владельца продукта)

1. **Тон статуса задачи «Новая»** — в макете нейтральный (серый), в правилах вёрстки было «оранжевый». Предложение: нейтральный — «Новая» задача ещё не требует действия так, как неоплаченный заказ.
2. **Два оранжевых статуса заказа подряд** («Новый» и «Ожидает предоплаты») в канбане визуально сливаются. Вариант: «Новый» — нейтральный, «Ожидает…» — pending.
3. **Дашборд «Сегодня»** — новый экран. Отдельного агрегирующего эндпоинта, скорее всего, нет; собирать из нескольких запросов (брони дня, заказы к оплате, кассы, смена) или попросить бэкенд о `GET /manager/objects/{id}/today`.
4. **Отчёты:** встраивать Superset как сейчас (`@superset-ui/embedded-sdk`, оформление ограничено) или рисовать свои графики по API в стиле дизайн-системы, как в макете. Можно гибридно: ключевые KPI своими средствами, детальные дашборды — Superset.
5. **Push или overlay на 1280–1440 px.** Push сжимает расписание недели до ~720 px. Если это мешает, порог push поднять до 1440 px.
6. **Мобильная версия** — только просмотр и быстрые действия (бронь, оплата, смена) или полный функционал. Макеты сделаны под полный, но настройки и отчёты на мобиле второстепенны.

## 5. Правила, которые легко нарушить при переносе

- Ни одного hex в стилях компонентов — только токены, иначе сломается тёмная тема.
- Одна оранжевая кнопка на шапку страницы и одна на футер панели; остальное — `btn`, `btn-dark`, `btn-ghost`.
- Белый текст на оранжевом недопустим (контраст) — `--on-accent` чёрный.
- Деньги — через один pipe/форматтер с неразрывными пробелами; не `toLocaleString()` в шаблонах (даёт узкий неразрывный пробел U+202F и разный результат в браузерах).
- Модалки не возвращать «временно». Если кажется, что нужна модалка, это почти всегда панель или inline-подтверждение. Единственное исключение — `Ctrl K`.
- Ссылка или кнопка внутри кликабельной строки не должна открывать панель строки (в макете это обработано в `app.js`, в приложении — `stopPropagation` на внутренних действиях).
