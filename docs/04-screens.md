# Инвентаризация экранов нового дизайна — по страницам

Дата: 2026-11-04. Источники: 12 макетов `new-design/*.html` (+ `index.html` — хаб, ссылки на экраны, без собственного контента), `assets/app.js`, `docs/01-audit.md`, `docs/06-markup-rules.md`, OpenAPI `BeInTeam Test API 8.2.23`.

Легенда:
- **API** — `METHOD /path`, подтверждён по `openapi.json` (есть в списке путей и методов).
- **«нет в API — уточнить»** — функция есть в макете, эндпоинта или поля в openapi нет. Не додумывать.
- Панели перечислены по `<aside class="drawer" id=...>` из HTML. Ключевые поля — по видимой разметке.
- Статичность: в макетах нет загрузки данных, фильтры и вкладки переключают только `.is-active`, таблицы — фиксированные строки. Это отмечено в «Заметках» каждой страницы.

Общий каркаж (во всех экранах): `sidebar` с пунктами из `app.js` (Работа: Сегодня, Расписание, Заказы, Клиенты, Задачи; Сеть: Объекты, Кассы, Чек-листы, Отчёты; Управление: Настройки), `topbar` (поиск `Ctrl K` → `GET /search`; чат WhatsApp и уведомления — пока только тост; переключатель темы), таббар на мобиле.

Сквозные «якорные» ссылки (`href="page.html#name"`) открывают панель по хэшу (`app.js`: `#name` → `#drawer-name`). Внимание: `orders.html#new`, `clients.html#new` ссылаются на несуществующие на этих страницах `#drawer-new` — панель не откроется (см. заметки в «Сквозных панелях»).

- **Маршрут:** `/login`
- **Назначение:** вход сотрудника по логину/паролю или через Telegram. Логотип «BeInTeam», слоган «Знакомая CRM. Новый характер.»

  - Primary-кнопка «Войти», разделитель «или», кнопка «Войти через Telegram».
  - Панелей нет.
- **Панели:** нет.
- **Данные для страницы:** нет (только форма).
- **Заметки:**
  - Вход: `POST /token` (тело `username`, `password`; ответ `access_token`, `refresh_token`, `real_user_id`).

  - Тексты времени и дат — MSK.

- **Назначение:** компания: общие параметры, тарифы и правила, график работы площадок, сотрудники и доступ, интеграции.
- **Блоки страницы:**

  - **График:** тумблер «Работает» — см. `day` / отсутствие записи — уточнить. Строки таблицы — список графиков по площадкам.
  - **Сотрудники:** «Пригласить сотрудника» (тост, панели нет). В API — `POST /users` (`UserCreateDTO`: `name`, `login`, `password`, `phone`, …) и `POST /company-users` (`user_id`, `company_id`, `rights[]`). Панели приглашения в макете нет — уточнить сценарий.
  - **Роли в компании:** «Администратор компании», «Сотрудник», «Тренер» — значения `rights[]` и контекст `GET /roles/{context}` не описаны в openapi (уточнить).
  - **Интеграции:** ЮKassa — ключ в `PATCH /companies/{company_id}` (`yookassa_key`), shop_id и флаги на объекте (`PATCH /objects/{id}`). WhatsApp — `GET /manager/companies/{company_id}/wchat-accounts`, `wchat_settings` (`accounts`, `header_key`) через `PATCH /companies/{company_id}`. **Telegram-бот входа — нет в API** (уточнить). Superset — `GET /reports/{company_id}`; `report_settings` в `PATCH` не принимается (уточнить). **Точка банк** — `GET/PUT/DELETE /system/admin/tochka/webhook/{object_id}` и `POST .../test` (системный админ-эндпоинт, доступ сотрудника компании — уточнить).
  - Таблица «Сотрудники» показывает «Последний вход» — в `UserDTO` есть `reauth_from`, `auth_allow_from`, поля «последний вход» нет (уточнить).

## Сводка API, не найденного в openapi

Все пункты, помеченные «нет в API — уточнить», и смежные неясности, сгруппированные по страницам.

**Вход**
- Сброс пароля «Забыли пароль?» — нет в API.

**Сегодня**
- Выручка за день, «К оплате сегодня», загрузка площадок за день — агрегаты, нет в API.

## Проверка (для исполнителя)

- Все эндпоинты, упомянутые в документе, сверены с `openapi.json`: 90 уникальных (88 дословно, 2 — по шаблонам `…/list-by-object/{source}/{object_id}` и `…/operation/{operation}`). Отсутствующий в openapi `GET /users` упомянут только как «нет в API».
- Все `data-drawer` в макетах ведут на существующие `id` (проверено по списку `<aside class="drawer" id=…>`).
- Drag-and-drop в макете — только атрибут; реализация в Angular — `PUT .../state/{state_id}` (см. «Заказы»).
